# 雲端快照備份與差異同步

Omera 配備原生的雲端備份與增量差異同步引擎（`src-tauri/src/cloud_backup.rs` 與 `src-tauri/src/cloud_sync.rs`），無需依賴第三方工具，即可實現資料庫一致性快照備份與遠端媒體檔案增量鏡像同步。

---

## 1. 支援的儲存服務類型

您可以在 **偏好設定 > 雲端備份與快照** 中設定遠端儲存端點：

| 服務類型 | 支援協定 / 服務商 | 技術特色 |
| :--- | :--- | :--- |
| **AWS S3 / 相容物件儲存** | AWS S3、Cloudflare R2、MinIO、Backblaze B2、Wasabi | 純 Rust 原生實作 AWS Signature Version 4 (SigV4) 憑證驗證與 HMAC-SHA256 簽署。 |
| **WebDAV** | Nextcloud、ownCloud、Synology DiskStation、QNAP NAS | 基於 HTTPS 的標準 HTTP Basic 認證協定。 |
| **本地 / 網路共享路徑** | 本機磁碟、外接 USB SSD、區域網路 SMB / NFS 共享目錄 | 直接執行極速檔案系統 I/O，完全無網路協定封裝額外損耗。 |

---

## 2. 資料庫快照備份

快照包含 `omera.db` 和 `manifest.json`，儲存圖庫記錄、標籤與評分，不包含媒體檔案、設定或憑證。在**設定 > 雲端備份**中設定目標，然後選擇**立即建立快照**進行手動備份。封存名稱唯一，本機發布採用原子操作。現有備份不會自動刪除。

### 自動備份

預設**關閉**，間隔為**七天**。啟用後選擇 **1–365 天**並**儲存設定**。取消或儲存失敗會保留原排程。Omera 執行時每 30 秒檢查，首次備份將在下次檢查開始；後續間隔從成功備份完成時計算。退出 Omera 會停止排程；關閉自動備份會停止後續工作，進行中的備份可完成。

**已儲存的排程**獨立於待儲存編輯顯示執行狀態、上次成功與嘗試、下次時間、封存和錯誤。失敗或中斷後等待**一小時**重試，重新啟動後也遵循此規則。更換目標會建立新排程，僅輪換憑證不改變時間。損壞的排程檔案會保留並暫停排程，修復後需重新啟動 Omera。

### 還原

還原會驗證快照，並暫存到下次應用啟動時啟用。請退出並重新啟動 Omera，僅重新整理視窗不足以啟用還原。啟動時會先將目前資料庫儲存為獨立的 `omera.pre-restore-<UUID>.db` 復原點，再以交易方式啟用快照。快照不能復原遺失的媒體或憑證。

## 3. 增量媒體映像與差異同步 (`cloud_sync.rs`)

如果說資料庫快照保障了元數據結構的安全，**差異同步 (Delta Sync)** 則負責為你龐大的高解析度實體圖片與影片檔案提供從本機到遠端的單向增量鏡像上傳保障。

### 同步引擎功能（已實現）：
- **差異比對策略**：
  - *快速指紋 (Fast Fingerprint)*：快速比對本機檔案大小與遠端檔案元數據（HEAD 查詢，速度最快，適合日常連線）。
  - *嚴格校驗 (Strict Checksum)*：以 SHA-256 雜湊值比對遠端（S3 為自訂標頭），保障位元組級精準一致。
- **權杖桶頻寬限速 (Bandwidth Limiter)**：可自訂上傳頻寬上限（KB/s，輸入 0 為不限速），避免背景同步傳輸佔滿工作室對外網路。
- **並行執行緒調節**：支援配置 1 至 16 個平行傳輸執行緒（預設 4 個）。
- **演練模式 (Dry-Run Mode)**：僅比對差異並產出待上傳與略過清單報表，不執行實際的檔案寫入。
- **即時進度監控**：持續發送即時進度事件，包含已同步檔案數、傳輸速率、預估剩餘時間 (ETA) 與當前傳輸檔案路徑，並支援不可部分完成協作式取消。

### 當前能力限制與規劃功能：
- **僅支援單向上傳**：當前同步路徑僅負責將本機已索引的媒體檔案鏡像上傳至遠端儲存，暫不提供從遠端拉取/下載媒體至本機的對齊能力。
- **無遠端刪除同步**：本機刪除檔案不會重疊刪除遠端檔案，遠端資料得以完整保留。
- **未啟用 ETag 差異核驗**：異動偵測基於檔案大小與 SHA-256 標頭資訊，服務商 HTTP ETag 不參與快取對齊。
- **規劃中雙向同步**：具備衝突裁決、遠端異動偵測與差異拉取的全功能雙向同步屬於後續版本規劃。
